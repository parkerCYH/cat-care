# 登入頁(Login)UI 規格

> 適用範圍:純手機版網頁,視窗寬度以 375px 為最小基準、430px 為上限,不考慮平板/桌面版面。

## 1. 頁面定位

未登入使用者開啟 app 時的唯一畫面。畫面本身很單純,只做一件事:**讓使用者主動點擊按鈕發起 Google 登入**,不做自動跳轉,避免使用者一開啟連結就被帶離 app、造成困惑。

## 2. 版面結構

```
┌─────────────────────────────┐
│                               │
│                               │
│           🐱                 │  ← App icon / 插畫
│         cat-care              │  ← App 名稱
│    記錄貓咪排便與體重的        │  ← 一句話說明
│      個人健康追蹤工具          │
│                               │
│                               │
│   [ 使用 Google 登入 ]         │  ← 主要動作按鈕
│                               │
└─────────────────────────────┘
```

- 畫面置中垂直排列:App icon/插畫 → App 名稱 → 一句話說明 → 登入按鈕
- 沒有頂部列、沒有漢堡選單、沒有返回箭頭——這是唯一「不套用共用導覽」的頁面,因為使用者此時還沒有任何可導覽的內容
- 「使用 Google 登入」按鈕樣式與首頁的快速記錄按鈕同等級的視覺重量(大按鈕、足夠的觸控高度 ≥ 48px),因為這是本頁唯一的互動

## 3. 互動流程

1. 使用者點擊「使用 Google 登入」→ 導向 Google OAuth 授權流程(交由 auth service 處理)
2. 授權完成後,auth service callback 導回本 app,前端取得登入狀態(token/session)
3. **登入成功後導向邏輯**:優先導回使用者原本想進入的頁面(例如分享連結是 `/weight/chart`,登入後直接進 `/weight/chart`);若沒有原始目的地(例如直接開啟 app 根網址),導向首頁 `/`
4. **登入後若使用者尚未加入任何 `cat_players`**(沒有貓咪、也沒人邀請):不在登入頁處理,直接進入首頁,由首頁自行顯示「還沒有貓咪」的空狀態並引導新增貓咪(見 4. 節)

## 4. 錯誤處理

- 若 Google 授權失敗或使用者取消授權:留在登入頁,顯示簡短錯誤提示(例如「登入未完成,請再試一次」),按鈕保持可再次點擊,不需要額外的錯誤頁面
- 若 auth service callback 失敗(例如網路錯誤):同樣停留在登入頁並提示重試,不嘗試自動重試

## 5. 與首頁的關聯

- 首頁需要新增「尚未加入任何 `cat_players`」的空狀態處理(不在登入頁處理),內容待首頁規格補充:顯示引導文字 + 「新增貓咪」按鈕,直接進入[貓咪管理](./cat-management.md)的新增流程

## 6. 待確認/開放問題

- App icon/插畫的實際美術素材尚未產出,目前規格僅描述版面位置
- 是否需要在登入頁提供「登出所有裝置」或隱私權說明連結?視 auth service 的合規需求而定,目前規格未涵蓋
- 登入 session 過期後(使用者操作到一半 token 失效),要導回登入頁還是原地彈出「請重新登入」提示?待後續規劃
