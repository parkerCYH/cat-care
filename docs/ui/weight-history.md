# 體重歷史(Weight History)UI 規格

> 適用範圍:純手機版網頁,視窗寬度以 375px 為最小基準、430px 為上限,不考慮平板/桌面版面。導覽方式與[首頁](./home.md)一致,採右上角漢堡選單,不用底部 tab bar。

## 1. 頁面定位

因為是腎臟病追蹤,體重的**變化方向**比單筆數字重要,但有時也需要查證某一筆的確切數值與備註。因此體重歷史拆成兩個獨立頁面,各自專注一件事:

- **`/weight/chart`(預設)**:趨勢折線圖,回答「體重方向對不對」
- **`/weight/table`**:表格列表,回答「某一天/某一筆到底記了什麼」

兩頁各自有獨立 URL,可直接分享/加入書籤/瀏覽器上一頁返回到正確的檢視模式。

## 2. 版面結構

### 2.1 共用頂部列

```
┌─────────────────────────────┐
│ ← 返回   體重歷史      ⇄  ☰   │  ← 返回 + 標題 + 切換圖示 + 漢堡選單
└─────────────────────────────┘
```

- 頂部列右上角新增一個「切換」icon(⇄,建議用圖表/表格互換的圖示),點擊即在 `/weight/chart` 與 `/weight/table` 之間導頁切換,不用額外的 tab 區塊佔用畫面空間
- 漢堡選單維持在最右側,行為與首頁一致
- 兩頁共用同一個頂部列元件,只有切換 icon 的目前狀態(顯示「切到表格」或「切到圖表」的圖示)不同

### 2.2 `/weight/chart`(折線圖頁)

```
┌─────────────────────────────┐
│ ← 返回   體重歷史      ⇄  ☰   │
├─────────────────────────────┤
│                               │
│        體重趨勢折線圖          │  ← 預設顯示全部歷史區間
│                               │
├─────────────────────────────┤
│ 區間切換:[ 全部 ] [ 1個月 ] [ 3個月 ] │
└─────────────────────────────┘
```

- **預設顯示全部歷史紀錄**,X 軸時間、Y 軸體重(公克)
- 單純體重線,不疊加排便異常標記(先做最簡單版本)
- 圖表寬度佔滿可用寬度,高度佔畫面可視高度 50–60%,是本頁視覺主角
- **資料點互動**:點擊/觸碰資料點彈出小提示框(tooltip),顯示日期時間、體重數值、量測方式、備註;觸控熱區建議 ≥ 44x44px
- **區間切換**:圖表下方提供「全部/1個月/3個月」篩選 chip,純前端篩選既有資料,不必重打 API
- 資料點稀疏(例如只有 1–2 筆)時仍需正常渲染

### 2.3 `/weight/table`(表格頁)

```
┌─────────────────────────────┐
│ ← 返回   體重歷史      ⇄  ☰   │
├─────────────────────────────┤
│ 日期時間            體重       │
├─────────────────────────────┤
│ 7/9 08:00          4.2 kg   ›│
│ 7/7 08:15          4.3 kg   ›│
│ 7/5 08:00          4.3 kg   ›│
├─────────────────────────────┤
│         載入更多 / 無限捲動      │
└─────────────────────────────┘
```

- 表格只顯示**日期時間、體重**兩個欄位,保持一覽的簡潔;每行右側箭頭(›)表示可點擊
- 點擊整行 → 導向獨立頁面 `/weight/:id`,顯示該筆的完整內容(日期時間、體重、量測方式、備註)
- 依時間新到舊排序,資料量大時採**無限捲動**,不做分頁按鈕
- 本頁不提供額外篩選列(日期區間篩選功能保留在圖表頁的區間切換;表格頁單純呈現全部歷史,靠捲動查找)

### 2.4 空狀態(Empty State)

- 兩頁皆適用:若完全沒有體重紀錄,顯示置中插畫/icon + 文字「還沒有體重紀錄」,並提供「回首頁記一筆」按鈕捷徑

## 3. 與首頁的關聯

- 首頁「最近紀錄摘要」區塊點擊體重相關項目後,預設導向 `/weight/chart`
- 兩頁皆**不提供**「記一筆體重」的入口——記錄動作統一收斂在首頁,避免功能分散

## 4. 待確認/開放問題

- 體重單位顯示是公克還是公克/公斤自動換算?後端固定存公克,前端顯示格式待定
- 未來若要加上排便異常疊圖(frontend-plan.md 原始建議),疊圖的視覺呈現方式(圖示 marker vs. 背景色帶)需要另外規劃,且只會加在 `/weight/chart`
- 資料點/資料列極多時(例如追蹤超過一年、高頻量測),折線圖是否需要抽稀(downsampling)、表格的無限捲動效能是否需要虛擬清單(virtualized list)?先觀察實際資料量再決定
